# Bot API reference

Find the operation you need, check its input and result types, and copy a complete request in your language.

Set your API base URL to `https://signal.arx.pro/bot-api/v1`. The routes below are relative to `/bot-api/v1`. Keep `ARX_BOT_TOKEN` in your environment; the SDKs read it when they create a client. Start with [authentication](authentication.md) and [making requests](making-requests.md) if you have not called the API before.

## Find an operation <a href="#find-an-operation" id="find-an-operation"></a>

- [Messages](reference/messages.md): Send, edit, copy, forward, delete, and pin messages in chats your bot can access.
- [Interactive messages](reference/interactive.md): Answer button presses and work with reactions, polls, and live locations.
- [Drafts and chat actions](reference/drafts.md): Show progress while your bot prepares a reply, then send the final message.
- [Files](reference/files.md): Upload reusable files, inspect their processing state, and download accessible bytes.
- [Updates and webhooks](reference/updates.md): Receive updates through polling or configure a webhook and inspect its delivery status.
- [Commands and profile](reference/profile.md): Set your bot's command lists, menu button, profile text, and avatar.
- [Groups and moderation](reference/groups.md): Read members, moderate supergroups, manage your bot's invite links, and answer join requests.
- [Topics](reference/topics.md): Create, edit, close, and delete forum topics in groups and private chats.
- [Inline and Mini Apps](reference/mini-apps.md): Answer inline, guest, and Mini App queries, and save prepared messages and buttons.
- [Payments](reference/payments.md): Create invoice links, answer pre-checkout queries, read plans, balances, and subscriptions, and refund charges.
- [Managed bots](reference/managed-bots.md): Read and rotate the tokens of bots you manage and set who can use them.
- [Business connections](reference/business.md): Read a business connection, update the connected account, and exchange encrypted messages.
- [Identity and platform](reference/platform.md): Check your bot's identity, read its effective limits, and manage its token.

## Shared request rules <a href="#shared-request-rules" id="shared-request-rules"></a>

The API returns successful JSON calls as `{"ok": true, "result": ...}`. The typed SDK methods unwrap `result`. File downloads return bytes, and `openapi.get` returns the OpenAPI document directly. Keep IDs as strings and read timestamps as UTC RFC 3339 values.

The SDK programs read `ARX_BOT_TOKEN`; each example lists its other environment variables. HTTP examples use curl and Python 3 to encode JSON from those same variables. The JSON responses illustrate the request using fictional bot and chat data; your IDs and timestamps will differ.

For a write, use a new `Idempotency-Key` for each logical action. It accepts 1 to 64 ASCII letters, digits, underscores, or hyphens. When retrying an action, reuse its key and the complete request, including binary files. The SDKs create a key when you omit one and retain it during their own retries. For retries across separate method calls, pass the original key explicitly. See [making requests](making-requests.md) for acknowledgement and PATCH rules.

## Common errors <a href="#common-errors" id="common-errors"></a>

A failed JSON call returns `{"ok": false, "error": {"code": "...", "message": "...", "request_id": "..."}}`. Use `error.code` to choose what to do; error messages may change. `field`, `reason`, and `details` may explain which input needs attention.

| HTTP | Condition | What you should do |
| --- | --- | --- |
| 400 | An input or parameter is invalid. | Check the named field and the operation's request rules. |
| 401 | The bot token is missing, invalid, or revoked. | Check your token and replace it if it has been revoked. |
| 403 | Your bot or the requested action is unavailable. | Read the error code and check the bot's status and access. |
| 404 | The resource does not exist or your bot cannot access it. | Check the ID and use resources visible to this bot. |
| 405 | The HTTP method does not match the route. | Use the method listed for the operation. |
| 409 | The request conflicts with the current state. | Follow the operation-specific recovery rule. |
| 410 | A bot was deleted, or a callback, upload session, cursor or snapshot expired. | Stop using the deleted bot or the expired resource. |
| 413 | A file or complete request exceeds its size limit. | Reduce the upload to the applicable limit. |
| 429 | A rate or capacity limit was reached. | Follow the retry advice in the error response. |
| 503, 504 | The request could not finish. | Retry according to the [error and retry guide](errors.md). |

This table describes shared failure categories. Each operation lists only the codes that need specific handling. The [error catalog](errors.md) has the complete codes, HTTP status values, and retry rules.
